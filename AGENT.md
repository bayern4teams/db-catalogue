# Agent entry point

This file exists for agents that look for singular `AGENT.md`. The canonical, complete instructions are [AGENTS.md](AGENTS.md); apply them in full, and also read [TECHNICAL_IMPLEMENTATION.md](TECHNICAL_IMPLEMENTATION.md) and [TODO.md](TODO.md) at task start.

Use source-code intelligence in the strict order **Graphify → Graft → Codebase Memory MCP → raw source tools**. Query existing Graphify results before broad search. If freshness is uncertain run `graphify update .`; Graft queries refresh automatically and `graft check` verifies; Codebase Memory normally watches, and manual re-index is only for known staleness. Prefer local AST/structural modes; avoid Graphify semantic/deep processing and `graft build --deep` without explicit need. Stop after the first system provides sufficient evidence; verify claims with targeted source reads.

Keep TODO.md live after every meaningful change, not after a work batch. Work hands on from TECHNICAL_IMPLEMENTATION.md: verify facts and commands, never guess. Ask the user about any question, suggestion, debt or missing evidence immediately, even mid-task. Seek approval before adopting a newly discovered better approach. Commit every completed and verified change. Never hardcode secrets, endpoints, models, paths, timeouts or thresholds in application logic; use validated config/secret references. `.env` is local and never committed.

Install hooks with `python scripts/install_hooks.py`; the pre-commit gate must update Graphify, Graft and Codebase Memory before commit, while post-commit refreshes the committed tree. Do not bypass failure. Generated graphs are not committed. Use `gh` and an installed `gh` skill to inspect GitHub Actions after pushing (`gh run list`, `gh run view`, `gh run watch`); do not claim CI passed before reading actual run results.

Use the complete [Ponytail](https://github.com/DietrichGebert/ponytail) workflow when available: `/ponytail [lite | full | ultra | off]` (default `full`), `/ponytail-review`, `/ponytail-audit`, `/ponytail-debt`, `/ponytail-gain`, `/ponytail-help`. In Codex use its `@ponytail-*` skill names after plugin installation. If unavailable, report that and perform equivalent minimal-design checks manually. Never trade away required tests, error handling or security.
