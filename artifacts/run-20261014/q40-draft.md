## Uncertainties

- ch.Location.companyID is Nullable(Int64) while ch.Company.companyID is String, yet the relationship is confirmed TRUE.
- Several TRUE relationships link two child tables (for example pg.companycontact.companyid -> pg.companyindustry.companyid, pg.companyexperience.companyid -> pg.location.companyid), and some are listed in both directions (pg.company/pg.location, ch.Person/ch.Experience/ch.PersonContact); no parent direction is stated.
- No relationship is listed for pg.companyrelation.relatedcompanyid, pg.companyinvestor.investorcompanyid, or ch.Company.companyID to anything outside ch.
- pg.company.companyid -> pg.companyindustry.companyid is TRUE but there is no pg.companyindustry -> pg.industryclassification link from company other than through classificationid.
- Many pg columns are text where another type would be expected (dates, latitude, longitude, flags such as ispublic, iscurrent); meaning is inferred only from names.
- Unclear differences: ch.Experience.jobTitle vs title, ch.Industry.name vs displayName, pg.company.entityname vs fullname, ch.Company.companyRevenue (String) vs companyRevenueIn000s (Int64) vs companyRevenueRange, types vs descriptors vs categories text columns.
- companyemployeecategory.category and firsthiredate meaning is unclear (an employee-size band, or a hiring category).
