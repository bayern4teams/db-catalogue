## Findings that block acceptance

**F1. A value is kept whole in `profiles.jsonl` (privacy, brief: "no value fragment ever kept").** `_shape_token` keeps every character that is not an ASCII digit and not `str.isalpha()`. Arabic-Indic, fullwidth, Devanagari and superscript digits, emoji and currency/check symbols come out verbatim (`'١٢٣٤٥٦'` -> `'١٢٣٤٥٦'`; `'😀💩🚀'` -> same). With `formats` keeping the top 8 shapes, a low-cardinality column of such values is stored entire. The SQL does the same (anything outside `[0-9]` and the engine's alpha class is copied through). PostgreSQL in a `C` LC_CTYPE database has `[[:alpha:]]` ASCII-only, so every accented letter would also be copied (unverified, needs P7-6). Fix: whitelist ASCII punctuation, map every other character to one class char (e.g. `_`). Tests: `test_no_value_made_of_other_characters_is_kept_whole[*]` (6). ASCII canaries, 10 000-char values, cap truncation (nothing after char 64 is used), `9{3}` look-alikes, empty string and NUL all PASS.

**F2. The flag makes the whole scan fail on an ordinary name.** `_quoted()` raises `ValueError` outside the `try` in `_profile_formats_postgresql` and `_profile_formats_clickhouse` (database/table). A table `Order Items`, a column `item id`/`item-id`, a schema/database `my-db` aborts the scan with the flag on; the same catalogue scans fine with it off (control passes). ClickHouse columns are skipped silently (no diagnostic). Fix: skip with a code-only `STATS_UNAVAILABLE` instead of raising. Injection is NOT possible (names must match `[A-Za-z_][A-Za-z0-9_$]*` before they reach SQL; hostile names never appear in a statement). Tests: `test_odd_names_skip_their_profile...`, `test_a_hyphenated_database_name...`.

**F3. "A budget limit costs profiles and never the catalogue" is false** (TECHNICAL_IMPLEMENTATION 8b, runtime comments, report). `budget.charge()` raises `BudgetExhausted`; `collect()` turns that into "no bundle was written". Running the profile pass last only means all the catalogue work is thrown away. One statement per eligible column against the default `max_queries=50`: a source with about 40 text/integer/uuid columns loses its entire scan the moment the flag is on. Fix: stop the profile pass (leave one code-only diagnostic) when `budget.used >= budget.max_queries`, as `_probe_clickhouse` already does. Tests: PG and CH budget xfails.

## Findings about wrongly dropped true links

**F5. Top-N truncation read as "never seen" (rule a).** The parent's list is its 8 most common shapes; the builder treats absence as disjoint. Quantified with the real `_Shape`/`_format_conflict`: a true FK whose child uses ONE existing code of a code/lookup table is dropped 2.0 % (10 codes), 18.5 % (20), 24.4 % (40), 28.1 % (100) of the time; ids 1..10^12 as text/int: a child confined to ids of 1-4 digits is dropped. The signal to avoid it is already in the data: a truncated list's shares sum to < 1. Fix: apply rule (a) only when the parent's list is complete (sum of shares >= 1 - epsilon), or when the absent token could not reach the child's share. Test: `test_a_child_shape_that_is_a_minority_parent_shape_beyond_the_top_n_is_kept` (control: a complete list without the shape still drops, passes).

**F6. MongoDB sample applied as if whole (rules a and b).** Ranges got `complete`; formats and lengths did not. Fixture: 300 string ids, first 50 `ORD-00001`, later `ORD-100051`; sample 50 gives parent shape `a{3}-9{5}` and length 9..9; a SQL child `ORD-1xxxxx` (shape `a{3}-9{6}`, length 10) is dropped by both (a) and (b). Fix: same rule as ranges (a sampled profile may mark, never drop) unless the read reached the end of the collection. Tests: two xfails.

## Implemented, unverified (needs the databases, P7-6)

- Real SQL never ran: regex classes, `WITH ORDINALITY`, windows over grouped shapes, `leftUTF8`, `\pL`, `toStringCutToZero`, `Nullable(FixedString)`.
- ClickHouse alias capture: CTE `v` aliases `t` and `x`; ClickHouse resolves a select-list alias across the query, so an integer column literally named `t` (or `x`) may take the String alias and silently lose its range (the range then fails `_exact_int`, no wrong value). Rename the CTE aliases to unlikely names.
- Cost: a full scan plus a regex pass per value per column, up to `read_timeout_seconds` each, with no overall time limit; partitioned parents (`p`) and their partitions (`r`) are both scanned.
- Engine letter-class disagreement (PG locale, ClickHouse `\pL`, Python `isalpha`) can make the same value tokenise differently across engines; with F1 fixed the effect is a missed rule, not a leak.
