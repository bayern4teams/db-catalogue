## Real defects (file:line, all in packages/requester/src/dbig_requester)
- **D-2 (DEC-7, blocks acceptance)**: `search.py:350-371` / `answer.py:152-166`. For a list question scoped to a source, the remaining question words are still searched (`match="any"`); when none of them matches, `search()` returns nothing and `ask` says NO_CATALOGUE_MATCH, so the source's objects are never listed. Reproduced with invented names, all NO_CATALOGUE_MATCH: "What does the ClickHouse database contain? List its tables." (the report's C3, verbatim), "Which tables does the postgresql source hold?", "show me the mongodb collections" (`collection`/`view` are not in STOPWORDS, `table` is), "What tables exist in clickhouse", "Give me the names of the clickhouse tables", "How many tables are in clickhouse". Only questions whose every other word is a stopword work. Suggested fix: when `objects_only` and `source_ids` are set and the term search finds nothing (or always), list the scoped source's objects (still bounded by retrieval_limit). Test: `test_dec7_list_question_with_ordinary_extra_words_still_lists_the_source` (6 cases).
- **D-1 (DEC-5, medium)**: `search.py:447-466` `relationships_for` orders by `(rank, id)` over all relationships touching any retrieved object. A hub with 25 declared links crowds the one candidate between the two tables the user named out of the default 20: "how does leaf relate to hub" gets 20 `spoke` edges and not the leaf-hub edge. Suggested fix: prefer edges whose two ends are both retrieved, then the status rank. Test: `test_dec5_edge_between_the_two_asked_objects_is_not_crowded_out_by_a_hub`.
- **D-3 (DEC-6, low-medium, pre-existing regex, kept)**: `answer.py:55` `LINEAGE_CLAIM = \b(derived from|flows into|writes to)\b` matches a single ASCII space only: "derived  from" (two spaces), newline, tab, no-break space, em space all pass as an accepted answer with a citation. Suggested: `derived\s+from` after `unicodedata.normalize("NFKC")`. Tests: `test_dec6_probe_whitespace_variants_of_claim_phrases` (5 fail).
- **D-4 (DEC-6, documented ceiling)**: paraphrases ("is fed by", "is populated from", "loads into", "is built from", and "the lineage of gadget is part") are accepted. The lead recorded this as a `ponytail:` ceiling; reported, not counted as a defect by itself. Tests: `test_dec6_probe_paraphrased_claims`.
- **D-5 (DEC-7, low, design ceiling)**: `answer.py:154-160` + `search.py:469-492`. Any question word equal to a source id, kind or name becomes a hard source filter and is dropped from the terms. A source called `sales` makes "tell me about the sales report" search only `sales`, missing table `sales_report` of source `ops` (NO_CATALOGUE_MATCH). No fallback to the unfiltered search. Test `test_dec7_source_id_equal_to_an_ordinary_word_probe`.
- **Note (not in scope, low)**: with the root logger at DEBUG the third-party `openai._base_client` logger writes the full request body (question, items, now also relationships) to the log. The app configures no logging, so the default is silent; an operator who sets DEBUG leaks it. Suggest a one-line mention in docs.
