## Controls that pass now and must keep passing
- Flag off: PG/CH/Mongo issue no profile statement, add no profile field, no `ranges.jsonl` rows; PG sampling on and flag off adds only the token reads.
- Missing profile on either side, a profile with no `formats`, an empty `formats`, or half a length range: no rule applies (6 + 1 cases). A declared FK is never dropped by the format or length rules.
- Boundary "keep" sides: 0.949, 0.9; touching length and integer ranges; wider child; one missing range sets no `numeric_ranges_overlap`.
- No downstream package (requester, planner, reviewer, render) names `ranges.jsonl` or `ValueRanges`; no `ranges.jsonl` tracked by git; `profile.schema.json` and `edge.schema.json` equal their models (so they must be regenerated if the models change); no corpus name in `packages/*/src`; no new float literal in `builder.py`, and none other than 0.0 / 1.0 in `runtime.py`, compared with `git show HEAD`.

## Assumptions the lead may overrule (all are constants or one-line names at the top of the test file)
- Config names: source `format_profiles` (bool, default false); builder `format_reject_share` (float, default 0.95, in (0, 1]).
- Bundle file `ranges.jsonl`, model `dbig_contracts.models.ValueRanges` (`field_id`, `object_id`, `minimum`, `maximum`, exact `int`, plus the usual Record fields), added to `COLLECTOR_FILES` and `MODELS`. A new schema file `value_ranges.schema.json`.
- Profile fields (in `profiles.jsonl`, on the `Profile` model or as extras; any `method`): `length_min`, `length_max` (int), `length_avg`, `digits_share`, `hex_share`, `uuid_share`, `alpha_share` (numbers), `formats` (dict token -> share). The dominant format is the largest share in `formats`. Absent or None means unknown; an empty `formats` claims nothing.
- Shares: of non-null values; digits-only counts toward `hex_share` or not (not pinned); a UUID is not alpha or digits.
- Rule (b) applies to text-family pairs only; integer-length ranges are not pinned. Rule (c) applies to integer-family pairs with a `ranges.jsonl` row on both sides, inclusive bounds.
- The SQL result is answered by alias: each profile statement must alias its top-level select columns with `length_min, length_max, length_avg, digits_share, hex_share, uuid_share, alpha_share, format_token, format_share` and, for integer columns only, `value_min, value_max`. Extra aliases are tolerated (answered None). The fake sets `cursor.description` (PG) and `result.column_names` (CH) and returns one row, so positional or name-based reading both work.
- Token grammar (tested as properties, not strings): characters are `9` (digit), `a` (letter, lower case), punctuation as is, and `{n}` counts. Same shape gives the same token, different shape a different token (letters first with `-` differs from digits first with `-` and from `_`).
- Diagnostics key: not pinned. "Any new `dropped_*` key on the builder run other than the three existing ones, an int, summing to the number dropped."
- Snapshot flag: `"numeric_ranges_overlap": true` appears in the candidate edge or the evidence rows it cites (the `candidate_text` helper); absent or null without two ranges. A dropped candidate has no edge, so `false` is never seen in a snapshot.
- Mongo profiles need `sample_rows > 0` and no token key; `_id` and other integer paths also get a range row.
- Old bundles without `ranges.jsonl` are not tested (adding the file to `COLLECTOR_FILES` changes the fixed file set; the lead decides about compatibility).

## Not covered here (attack mode / live)
- Live PG+CH: the real SQL (regex classes, token expression, run-length, dominant-token subselect, `uniq`/`topK` cost) on real columns, `statement_timeout` / `max_execution_time` against a large column, one scan's total cost, and the plan acceptance (0 PG<->CH candidates in context with 0 owner-true pairs lost). Needs the databases (not up, owner 2026-10-24; DEC-40 says live checks come with P7-6).
- ClickHouse default values: `min`/`max`/`length` over an EMPTY non-nullable table return 0, not NULL, so an empty table may look like range [0,0] and a length 0; no test can tell without a row count. Attack: an empty child or parent table, an all-NULL column, a column of empty strings.
- A dominant token present in the parent only in a lower-ranked position when the parent profile records few formats (how many formats are kept is the worker's choice; it must not be a hardcoded number, plan 2.4).
- Mongo mixed types in one path (strings and ints), arrays (`path[]`), `Decimal128`/`Int64`/`ObjectId`, values over `max_sample_bytes`.
- Positive measured value overlap with a format/range mismatch (contradictory data): not specified; attack should look at which wins.
- Case folding in tokens (`AB` vs `ab`), Unicode letters and digits (PG `[0-9]` vs `\d`, CH `\d`), very long values, a value that looks like a format token, NUL bytes.
- Sampling bias: Mongo ranges and formats come from the first documents only (a sample), while PG/CH are whole-column; a Mongo range from a sample could drop a true link (rule (c) with a sampled range). Consider whether Mongo ranges should be excluded from rule (c).
- Integer ranges of a column beyond 64 bits, unsigned 64-bit values in a JSON reader, and a bundle written by an older collector.
- The scan queue and requester path: the `sample` capability check was tested at `accept_scan`/`process_next` only.
