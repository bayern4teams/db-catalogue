# Acceptance: P7-8 (F18) value-free `error.reason` on model failures

Derived from `docs/plans/PHASE7_LOCAL_PLAN.md` section 4 "P7-8" and section 2 only. Implementation not read.
Checks: `tests/phase7/test_p7_8_failure_reason.py` (79 tests; no `__init__.py`, like `tests/catalogue_fixes/`).
Run: `uv run --python 3.12 pytest -q -p no:cacheprovider tests/phase7/test_p7_8_failure_reason.py`

## Spec the tests assume (key names are constants at the top of the file; change them there if the lead names them differently)
`error.code` unchanged; `error.reason` = dict, keys only from: `exception` (class name), `schema_errors` (list of pydantic
error types), `finish_reason`, `reply_length` (int), `citation_check` (`unknown_id` | `none`). A key that does not apply is
absent or None. No reply text, ID, field name or value anywhere.

## Checks
| Cause (ModelStub) | Code (unchanged) | Reason asserted |
|---|---|---|
| invalid JSON | UNAVAILABLE_OR_INVALID | `ValidationError`, `["json_invalid"]`, finish `stop`, length = body length |
| missing `outcome` | same | `["missing"]` |
| extra field | same | `["extra_forbidden"]` |
| outcome outside the set | same | `["literal_error"]` |
| finish_reason length, partial / empty body | TRUNCATED | finish `length`, length = body length (0 allowed), no schema errors |
| citation of an unknown id | INVALID_CITATION | `citation_check == unknown_id` |
| answered, no citation | INVALID_CITATION | `citation_check == none` |
| answer over `max_answer_chars` | ANSWER_TOO_LONG | length is the reply's, not the limit |
| lineage claim | UNAVAILABLE_OR_INVALID | reply fields set, no schema errors, no citation check |
| closed port | UNREACHABLE | `APIConnectionError`, no reply fields |
| delay > timeout | TIMEOUT | `APITimeoutError` |
| HTTP 400 / 500 | REJECTED / UNAVAILABLE | `BadRequestError` / `InternalServerError`; server body text absent |
Every cause: only the 5 keys; `exception` an identifier; `schema_errors` types from a closed set; `reply_length` an int; no
`answer`/`citations` in the result. The three causes that share one code differ in `reason` (the point of F18).

Canaries: one unique string planted in the reply text, a fake citation id, an extra field name and value, an invalid-JSON body,
a truncated body, an enum value. Absent from `json.dumps(result)` and from the application's log (DEBUG; openai/httpx loggers
excluded as in the C1 test) for all 14 causes, and from captured stdout/stderr. Control test shows the replies really carry it.

CLI: `dbig-requester ask` (CliRunner, real TOML) prints `error.reason` with `["extra_forbidden"]` and no canary.
Telemetry: with `_trace` replaced by a fake span (records any method), some call carries a dict containing every item of
`reason`, `end()` is still called once, no canary in the calls; a span that raises on every call leaves the result intact.

Controls that pass today (6 plus the canary/log checks): good answer has no error; `not_established` is not a failure;
`NO_CATALOGUE_MATCH` stays `{"code": ...}` with no reason; canary replies carry the canary.
