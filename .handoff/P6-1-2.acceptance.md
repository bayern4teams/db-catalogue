## Interpretations and consequences for the lead

- Range semantics are assumed from the spec text: `contained_fraction` is shared over the child
  values inside the range (so 1.0 for a true child), and `shared_tokens` is counted inside it. If
  the implementation keeps whole-child denominators, three tests (true child, quarter overlap,
  two capped sides) need the spec's wording settled, not silently relaxed.
- The label check uses the spec's quoted phrase "a zero is not a measurement" and, for too-thin
  ranges, "not measured". The reason code's spelling is not asserted, only that it is new.
- `catalogue_fixture_kit.token_set` emits no `complete`, so after P6-2 every existing test that
  expects a disjoint drop (`test_a1_overlap.py`, `attack2_a1_overlap.py`, others using the kit)
  will see "flag absent = false" and stop dropping. The lead should have the kit emit
  `complete=True` (or flip those tests on purpose and name them in the commit), as the plan says.
- Section 2.4 names: `test_no_corpus_literals.py` already globs this directory, so it covers
  this file; no duplicate added. Hard-coded numbers (256, 3,940, 100) are not greppable by name;
  the reviewer's `git diff` check from `.handoff/PHASE0.acceptance.md` applies to the src diff.
- Not covered (needs live data): the replay of 0 true pairs dropped and 16 known-wrong dropped
  with the owner's settings (DEC-19).
