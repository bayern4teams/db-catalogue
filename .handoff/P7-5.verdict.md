## Findings (tests that fail)
1. MEDIUM, qualified-name collision (DEC-36 format): table `a.b` in source `alpha` and table `b` in namespace `a` both qualify to `alpha.a.b.gadget_id`; one `confirmed` entry verified both (`test_a_dotted_name_cannot_collide_with_a_namespace_split`). A decision can verify an unintended pair and make it visible to the model. Fix: when two proposed candidates share a key, apply to neither and count it as ambiguous (no names logged).
2. LOW, exactly `c_min` not honoured for non-terminating fractions: the tier compares the stored `contained_fraction`, which is rounded to 6 places. 4 of 12 = 1/3, `c_min = 1/3` gives 0.333333 < 0.3333333333333333 so it is not verified (both complete and bound). Default 0.25 is exact, so the default is unaffected. Fix: compare `shared / len(child_set)` unrounded (e.g. carry the `estimate` key, or compare with a 1e-6 tolerance).
3. LOW hardening, `decisions_file` is read without a size bound: `/dev/zero` under a 1 GB address limit raises MemoryError, not ValueError (planner bounds its inputs the same way). Fix: read at most a configured/derived bound or `stat` first.
4. LOW, a UTF-8 BOM file is refused (clean ValueError, message does not say why). Fix: read with `utf-8-sig`.
