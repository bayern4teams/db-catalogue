## Controls that pass now and must keep passing
- E (DEC-34): `forbidden_source_pairs` (both orders) and `source_groups` block every candidate between two sources (two candidates, opposite directions); `allowed_source_pairs` is not a config key.
- B guards: a zero against a complete parent drops under the old count only; a positive overlap or an unmeasured sample never drops; no estimate / a profile without `distinct_estimate` / an estimate of 0.0 does not drop or crash.
- Requester premises (fixtures yield exactly the expected candidates, retrieval reaches only the ends); declared key unaffected by the flag; index state still holds the relationship (the filter is applied when answering).
- Planner keeps verified cross-source, plausible same-source and old no-tier edges by default.
- Plan 2.4: no threshold/flag literal outside `config.py`, no `0.25` in `builder.py`, no corpus names, requester/builder do not import the planner.

## Assumptions the lead may overrule
- Field name `Edge.evidence_tier`; config names `c_min`, `min_expected_shared`, `decisions_file` (BuilderConfig), `include_unverified_cross_source` (AnswerConfig and PlannerConfig). `c_min` pinned to refuse -0.1 and 1.5; `min_expected_shared` to refuse -1. 0 is not pinned.
- Containment for `verified` is the point estimate (contained fraction of the child's distinct values compared), not the Wilson lower end; 0.25 exactly is verified.
- The tier of a DECLARES_FK edge may be None or `verified` (pinned loosely); other kinds must be None.
- Diagnostics key names are not pinned: B is "any new `dropped_*` key on the builder run other than the two existing ones", summing to 1; unmatched decisions is "the one integer key on the run containing `decision` or `unmatched`", value 2. Both keys appear only when non-zero is NOT pinned (zero may be absent or 0).
- A rejected decision sets the edge status `rejected` (tier unpinned); a confirmed decision sets tier `verified` (status unpinned).
- The decisions entry orientation is child -> parent as written; a swapped entry is unmatched.
- The planner flag is tested through `find_paths` (join); whether the unverified edge is also absent from `graph.json` `references` is not pinned.
- Requester filtering is at answer time (the flag is in `AnswerConfig`); the index may keep the edge (premise test asserts it does, which constrains an implementation that filters at index time).
